Before I take it on

Not every problem should be solved with code.

Feasibility is case by case, and I'd rather tell you that on the first call than three weeks in. Every project gets read against four questions.

01

Is it real work?

Something a person does repeatedly, on a schedule, with rules that can be written down.

02

Can it reach the data?

If the systems involved have an API or an export, it's buildable. If it's locked in someone's head, we start there.

03

Is the cost obvious?

Hours saved, deals lost, errors caught. If the value can't be named, the project can't be scoped.

04

Will anyone use it?

Software nobody opens is the most expensive kind. I want to meet the people who'll live in it.
